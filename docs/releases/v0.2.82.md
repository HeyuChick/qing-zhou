# v0.2.82 — 手动通知支持邮件批量与变量模板

## 功能增强

### 手动通知 · 多渠道
- 手动通知支持 **Telegram / 邮件 / 两者同时** 三种渠道。
- 邮件按用户批量发送：覆盖全部正常用户或指定部分用户，逐位快照邮箱并保留发送结果（成功 / 失败 / 未发送）。
- 发送历史与明细页展示每位用户的渠道、邮箱、状态与原因；失败、未发送分别统计。

### 手动通知 · 变量模板
- 标题与正文支持 `{{username}}`、`{{email}}`、`{{site}}`、`{{panel}}`、`{{plan}}`、`{{expiry}}`、`{{used}}`、`{{total}}`、`{{remaining}}`、`{{remain_pct}}`、`{{points}}` 等占位符，发送时按每位用户替换（Telegram / 邮件共用）。
- 编辑器提供可点选插入的占位符，未知变量原样保留，订阅地址等凭据不进入变量。
- 已开启自动续费提醒等原有 Telegram 通知能力保持不变。

## 技术改进
- 手动通知接收人表改为主键 `(notification_id, user_id, channel)`，支持同一位用户多渠道投递；旧库自动迁移，历史数据保留。
- 服务重启后未完成通知转为「unknown」状态，避免重复发送（Telegram / SMTP 无幂等发送标识）。
- 新增邮件送达与变量替换的单元测试；前端发送历史测试保持全绿。

## 验证与运行说明
- 验证命令：`go build ./...`、`go vet ./...`、前端 `npm test`、`npm run build`。
- 邮件渠道需先在「系统设置」里配置 SMTP。
- 升级会自动执行数据库迁移，无需手工操作。
