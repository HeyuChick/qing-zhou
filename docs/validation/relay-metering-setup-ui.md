# 中转计量设置与下发状态

## 操作流程

1. 在服务器页展开“中转链路计量”，修改开关并选择“检查变更影响”
2. 预检只读取当前拓扑和既有内核检测记录，不保存设置、不生成凭据、不连接节点、不安装内核
3. 检查受影响机器、统计能力、Vision 修复要求及检测失败或过期原因。预检不代替运行中内核核验
4. 明确确认内部凭据、配置重启和采集交接影响后，才保存并排队下发
5. “设置已保存”只说明保存请求已被接受；节点下发与链路切换分别显示，所有节点错误逐项列出

所有原有开关默认值保持不变。旧凭据仍需独立确认停用或恢复；逐用户旧代提交保留 `user_id`，不把多个用户的旧代合并为同一目标。

## 状态契约

- `GET /api/admin/relay-metering/preflight` 接受 `enabled`、`cumulative_enabled`、`per_user_enabled` 布尔查询参数。验证复用真实保存规则，事务回滚；返回 `valid`、`errors`、`nodes` 和说明
- 节点预检列表包含面板本机和全部启用服务器，因为保存采用全量下发；配置实际变化或服务需要恢复的节点才需要重启
- `PUT /api/admin/relay-metering` 及凭据变更响应附带 `sync_ticket: {epoch, revision}`
- 状态响应附带 `sync_epoch`，每条同步记录附带单调 `revision`。整体记录另含 `request_revision`（该轮覆盖的最新排队请求）及 `started_revision`
- 新请求到达正在执行的旧轮次时，旧轮次完成仍保留自己的请求水位，不能将旧成功误报为新请求完成
- 控制器重启后 epoch 改变；旧票据不能用新进程从头计数的 revision 确认。票据不是持久任务记录，也不授予操作权限
- UI 只有在 epoch 一致、整体请求水位覆盖票据、各节点结果比本轮开始记录更新时才显示本轮成功。未知、旧结果和缺失结果保持等待
- 界面每次保存后最多自动读取 60 次，间隔 2 秒；错误、整体终态、关闭面板或离开页面会停止。暂停后可手动继续检查
- 关闭或切页会取消读请求并作废其返回值，不撤销已经提交的设置；在途保存仍有独立锁，防止重新展开后重复提交

## 回归覆盖

- 组件测试：开关默认值、累计模式保护、预检错误与完整节点能力、确认/取消、重复点击、所有节点错误、保存与生效分离、旧成功、并发旧轮次、重启 epoch、缺失 epoch、保存失败、有限轮询、取消与过期返回、旧代 user_id
- 后端测试：只读预检无数据库/调度副作用、参数验证、受影响机器名称、探测失败与未知能力、控制器 epoch、并发请求合并及旧轮次不能确认新请求
- 入站批量启停：每条失败原因保留，失败设置不改变且继续选中；只为成功保存项启动后续状态检查
- 原生中转落地选择器同时包含 AnyTLS 和 Hysteria，继续排除只支持入口的 mixed

真实浏览器验证应覆盖桌面与窄屏布局、确认前不产生 PUT、保存后旧节点结果仍等待、两个节点同时失败时原因完整显示，以及折叠/离开后无继续轮询。组件测试与构建不能代替真实浏览器或生产链路验收。
