# 逐用户旧凭据退役与采集 SQL 优化

## 安全边界

本轮只修改代码并使用隔离 SQLite / loopback 测试；不会运行生产数据清理。

P1 的旧逐用户凭据现在出现在已有「兼容凭据」管理界面，使用与 P0 相同的明确确认、管理员操作、重建下发机制。它不会自动退役。当前代不能退役；删除线路、禁用用户但没有同物理链路替代代的历史凭据继续保守保留，不能据此宣称所有旧配置已自动清空。

可以手动退役的条件：

1. 同物理链路、同 owner 的新一代处于实际来源配置验证后的 `active` 状态，且 P1 仍启用
2. 最新已确认的来源配置不再包含旧 outbound tag、身份名或旧 UUID/password/auth/SS2022 用户密钥；重命名 outbound 不能绕过检查
3. 从来源移除确认、新代激活、旧身份最后正流量、来源/落地最后采集缺口中的最晚时点开始，经过至少两个完整采集周期
4. 来源和落地均有至少两次不同采集时刻的成功批次，覆盖安静窗口且近期成功状态正常；任一端还有 pending 批次或有效采集租约（网络读取尚未持久化）则拒绝

这是受管配置与可观测流量证明，不等同于远程活动连接清单；配置重启仍可能中断暂时空闲的已有连接。管理员仍须确认手工配置的消费者已迁移。

`retiring` 表示已请求从目标认证对象中排除，并不等于节点已执行；只有目标最新实际应用配置中不再出现旧凭据才变成 `retired`。原始身份行、加密凭据、owner/link/generation 映射始终保留，因此迟到流量仍归原 owner 且不重复扣套餐。恢复使用 `restoring`，目标配置须正确安装完整协议认证对象、匹配目标入站且恢复统计身份，才能回到 `active`。重复 wire credential、错误认证对象或旧配置回执不能虚报恢复成功。后续目标配置回滚若重新带回旧认证，状态退回 `retiring`；若恢复后的认证再次缺失或不匹配，状态退回 `restoring`，不会继续虚报已应用。

退役仅减少运行配置中的认证对象。不会删除历史数据库行；禁用 owner 也不会被恢复操作自行授权。

## 采集优化与可复现证据

命令：

`QZ_METERING_SCALE=1 go test ./internal/store -run '^TestTrafficLedgerSQLScale$' -count=1 -v`

同一隔离 SQLite fixture（非生产容量承诺），实测 SQL 为驱动执行的语句数，不含 BEGIN/COMMIT/ROLLBACK：

| counter 数 | 批次 | 原 SQL | 优化 SQL | 原单次耗时 | 优化单次耗时 |
|---|---|---:|---:|---:|---:|
| 100 | 零增量 | 1010 | 416 | 19.6ms | 13.5ms |
| 1000 | 零增量 | 10010 | 4016 | 252.1ms | 93.9ms |
| 1000 | 首次正增量 | 11010 | 5016 | 346.0ms | 98.5ms |
| 1000 | 再次正增量 | 11010 | 5016 | 515.4ms | 123.6ms |
| 1000 | 新 epoch | 11011 | 5017 | 717.5ms | 113.1ms |

时间是共享云端环境的一次诊断结果，会受竞争、缓存、SQLite/WAL 和硬件影响；SQL 数更适合确定性比较。1000-counter 零增量语句减少约 60%。相同批次重放前后均为 2 条 SQL。

实现只批量化事务内读写：P1 不变身份一次批量 lookup/INSERT，已处理标记、冻结 binding、当前 epoch 游标和之前 pending counter 集合各读取一次。不跨事务或跨 epoch 缓存。普通用户/旧命名空间仍使用原碰撞、归属和套餐解析规则。每 counter 的 savepoint、游标、绑定行、observation 行全部保留。

因此本轮**没有降低审计行增长率**。1000 counters 每 10 分钟一次、保留 90 天，binding/observation 仍各约 1296 万行；没有用少记零流量或删审计证据换性能。进一步压缩需要单独的无损表示、报告/重放兼容和迁移方案。

覆盖：零/正增量、进程 epoch、乱序、相同批次重放、部分失败重试、旧 owner 冻结、来源错配、未知身份与缺口、原始数据到期后去重墓碑保留。原 90 天 raw / 两年日汇总策略未改。

## 迁移与回退

追加迁移 `000009_relay_user_retirement`，不修改版本 1–8：新增独立可恢复状态表，审计追加 `user_id`，新增安静窗口查询索引。没有自动退役、数据回填删除或身份重分类。DDL 与版本标记同事务；覆盖升级、重复迁移和索引失败全回滚测试。

先在备份副本验证并保留升级前一致性快照。运行层撤销退役应使用界面的「恢复」并等目标实际应用确认。数据库升级后旧二进制会按现有未知版本保护拒绝启动，不能通过删除版本标记回退。若必须回退二进制，按灾难恢复流程停服、保留当前数据库副本、恢复配套升级前快照；快照之后的业务写入需另行处理，不能自动丢弃。
