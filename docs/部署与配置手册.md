# 轻舟面板 · 部署与配置手册

> 管理员向。从零把「轻舟 + sing-box」跑起来，并接入节点、套餐、订阅。

## 总体架构

轻舟是**单文件 Go 程序**（内置 Vue 前端 + SQLite），负责：用户/套餐/订阅/统计/可视化管理。
真正承载流量的是 **sing-box**（独立 systemd 进程）。轻舟生成 sing-box 配置并下发，
通过 sing-box 的 `v2ray_api` 采集每用户流量。一台机器可同时跑面板和 sing-box；
也可面板在中心机、落地 sing-box 在多台机器（面板用 SSH 下发）。

## 一、安装 sing-box（一键）

在**每台要做落地的服务器**上执行：

```bash
# 脚本由面板托管，把域名换成你自己的面板地址
curl -fsSL https://<你的面板域名>/install-singbox.sh | bash
```

> 面板「**系统设置 → 面板访问地址**」里会依据你配置的地址生成**可一键复制**的完整命令，
> 无需手工拼域名。地址来源优先级：环境变量 `QZ_PUBLIC_BASE` > 设置页「访问地址」> 反代头/请求 Host。

脚本会：

1. **已装则自动检测**，打印版本与路径，不重装（要重装加 `--force`）；
2. 未装则安装**官方最新版**（含 `v2ray_api`，统计依赖它）到 `/usr/local/bin/sing-box`；
3. 建 `/etc/sing-box/config.json` 占位配置 + `sing-box` systemd 服务并启动；
4. 应用**网络内核调优**（BBR + fq + 收发缓冲区 + somaxconn + tcp_notsent_lowat + 文件句柄上限，要跳过加 `--no-tune`）；
5. 最后打印一段「服务器」信息，照着填进面板即可。

输出示例：

```
════════ 安装完成，请到面板「服务器」处填写 ════════
  服务器地址(host)   : 1.2.3.4
  SSH 端口           : 22
  SSH 用户           : root
  sing-box 二进制     : /usr/local/bin/sing-box
  配置路径(config)   : /etc/sing-box/config.json
  systemd 服务名      : sing-box
  v2ray_api 监听      : 127.0.0.1:18080
```

> 占位配置是空的，sing-box 会先空跑；面板接管后会用真实配置覆盖并重启。

## 二、部署轻舟面板

1. 把 `qingzhou` 二进制放到 `/opt/qingzhou/qingzhou`（`chmod +x`）。
2. 写 `/opt/qingzhou/qingzhou.env`（`chmod 600`），常用变量：

   ```ini
   QZ_LISTEN=127.0.0.1:8081
   QZ_DB=/opt/qingzhou/qingzhou.db
   QZ_PUBLIC_BASE=https://你的面板域名      # 可选：面板访问地址，也可在「系统设置」里填；设了环境变量则以其为准
   QZ_SECRET_KEY=<openssl rand -hex 32>    # 加密库内敏感配置的主密钥，务必设置
   QZ_SINGBOX_CONFIG=/etc/sing-box/config.json
   QZ_SINGBOX_UNIT=sing-box
   QZ_SINGBOX_BIN=/usr/local/bin/sing-box
   QZ_SINGBOX_V2RAY=127.0.0.1:18080
   # 探针监控（可选）：探针二进制所在目录，面板据此提供下载。默认相对路径 cmd/probe/dist，
   # 二进制部署时几乎必设为绝对目录，见下「探针监控」。
   QZ_PROBE_DIR=/opt/qingzhou/probe
   # 初始管理员（仅首次启动生效）：不设 QZ_ADMIN_PASS 则随机生成并打印到日志
   # QZ_ADMIN_USER=admin
   # QZ_ADMIN_PASS=
   # 可选 SMTP（邮箱验证/找回）：QZ_SMTP_HOST / QZ_SMTP_USER / QZ_SMTP_PASS ...
   ```

   > 说明：JWT 密钥由程序**首次启动自动生成并存入数据库**，无需手动配置；`QZ_SECRET_KEY`
   > 是用于加密库内敏感配置（SMTP 密码 / Reality 私钥等）的主密钥，建议置于环境变量、不入库。

3. 装 systemd 服务（仓库 `deploy/qingzhou.service`）：

   ```bash
   cp deploy/qingzhou.service /etc/systemd/system/
   systemctl daemon-reload && systemctl enable --now qingzhou
   ```

4. 前置 Nginx/Caddy 反代到 `QZ_LISTEN`，配 HTTPS（订阅与面板都走 https）。
5. 备份：仓库 `deploy/backup.sh` 挂 cron（每日热备 SQLite，留 7 天）。

首次访问会建管理员账号（或用初始账号登录后改密码）。

## 三、面板内配置顺序

> 入口在后台左侧菜单。建议按此顺序一次配好。

### 1. 服务器（多落地才需要）
本机落地直接用默认值即可。远程落地：**服务器 → 新增**，填安装脚本输出的 host/SSH/路径。
面板会 SSH 校验并下发配置。

### 2. TLS / Reality
**节点管理 → TLS**：
- **Reality**（推荐）：一键生成 x25519 密钥对 + short_id，填一个**借用域名**（`handshake server`，
  如 `www.microsoft.com`）。抗封锁、无需自有证书。
- **证书 TLS**：有自己的域名证书时用；可直接引用「证书管理」里的证书（见 2.1），也可就地粘贴或一键自签。

#### 2.1 证书管理（真实证书 / 自动续期）
需要真实证书的场景（套 CDN 的 WS-TLS、想让浏览器/系统信任的 mixed HTTPS 代理等），到 **sing-box → 证书管理** 统一签发和托管，证书**全局复用**、可被任意入站的 TLS 引用：

- **ACME 在线签发**（Let's Encrypt）：默认走 **Cloudflare DNS-01**——先在「**系统设置**」填一个 Cloudflare API Token（权限：`Zone → DNS → Edit`，作用域含该域名的 Zone），再在证书管理里填名称 + 域名一键申请；也支持 `http-01` / `webroot`。签发在**面板所在机**完成，不需要落地机开 80 端口。
- **粘贴导入**：把已有的证书 PEM + 私钥粘进来（域名默认取证书 CN）。
- **一键自签**：给定 SNI 生成自签证书，适用于 TUIC / Hysteria2 等允许 `insecure` 或用证书指纹的客户端。
- **自动续期**：ACME 证书默认开启自动续期，后台定时器在临近到期时续签并**推送到引用它的各落地机**；也可在证书列表手动「立即续期」。粘贴/自签证书不自动续，到期需重新导入。
- 仍被 TLS 配置引用的证书不允许删除。

> 证书密文用 `QZ_SECRET_KEY` 加密落库；换过该密钥会导致旧证书解不开，列表会标记「无法解密」，此时拒绝写回以免覆盖成空。

### 3. 入站（节点）
**节点管理 → 入站**：选协议建入站，绑定上一步的 TLS。推荐组合见下「协议选型」。
同一台机可建多协议入站（vless/hysteria2/tuic…），用户订阅会自动聚成「固定IP·只切协议」优选组。

#### 3.1 中转 / 落地链路（可选）
让 A 机做**线路机**、B 机做**落地机**：`客户端 → A 入站 → B 入站 → 互联网`。适合国内到线路机链路好、线路机到落地机再出海的场景。

- 在 A 的入站里把「**落地 / 中转**」设为 B 上某个入站；或在 **sing-box → 链路拓扑** 里给 A 入站点「**＋ 串联落地**」直接新建 B 落地并自动关联。
- 面板会在 A 生成一个拨号 B 的出站 + 路由，并在 B 的入站里注入一份**自动派生的中转凭据**（无需你手工配隧道）；两端凭据同源。
- **支持多级链式**：B 本身也可再设一个上游落地 C，链成 `A → B → C → 互联网`（拓扑图逐级展示、并自动防环）；末端还能接一个第三方代理出口（见下）。
- 约束：落地入站需为可作出站的协议（vless / vmess / trojan / shadowsocks / hysteria2 / tuic）；per-user 流量计量始终在**入口 A 侧**完成。
- 「链路拓扑」里可一键「**解除中转**」恢复直接出网。

#### 3.2 第三方代理出口（可选，静态 IP）
让某入站不直接出网，而是经一个**购买来的 SOCKS5 / HTTP 代理**（例如固定住宅/机房静态 IP）出网 —— 出口 IP 即该代理的 IP。

- 在 **sing-box → 代理出口** 录入代理（类型 socks/http、地址、端口、账号密码，密码库内加密存储）；再在入站的「**代理出口**」里选它。「代理出口」与「落地 / 中转」**二选一**。
- **HTTP 代理只转发 TCP**：TUIC / Hysteria / QUIC 等依赖 UDP 的入站请改用 **SOCKS5** 出口，否则 UDP 静默失败。
- 代理若因换了 `QZ_SECRET_KEY` 解不出密码，出站以空密码下发让流量在代理侧「**fail-closed**」，不会悄悄回落成直连（避免暴露真实 IP）。
- 仍被入站引用的代理出口**不允许删除**。

### 4. 分组
**分组**：把节点归类（如「免费」「高级」「自建」）。订阅/套餐都按分组授权。
- **免费分组**：在「设置」里指定 `free_group_id`，所有用户可见；不想送就设「不设」。

### 5. 套餐
**商品**：建套餐（流量包 / 套餐型），绑定可访问的分组。
- 重复购买同套餐会**排队生效**（不再叠加：新买的份排队，当前份用完/到期后自动顶上），不同套餐各自独立计费（桶模型）。
- 退款默认**按剩余流量/时间比例**结算（可在「系统设置 → 退款策略」调整方式/基准/手续费）。
- 下架被订阅的商品要走「**下架**」流程（二次确认→按比例退积分→清空订阅者套餐），不要硬删。
- 完整的购买 / 续费 / 多套餐 / 退款规则见 **[计费与退款业务说明](计费与退款业务说明.md)**。

### 6. 机场订阅源（可选）
**节点源**：粘贴机场订阅链接，可绑定分组、定时抓取（支持 base64 / Clash YAML）。

### 7. 探针监控（可选）
在每台服务器装轻量探针 `qingzhou-probe` 上报 CPU/内存/磁盘/负载，面板「服务器监控」展示并告警。

- 安装命令在「**服务器监控**」页获取，形如 `bash <(curl -sL <面板地址>/api/monitor/install.sh) <探针Token>`；
  脚本里的面板地址同样取自上面的「访问地址」（`QZ_PUBLIC_BASE` > 设置页 > Host）。
- **探针二进制由面板托管下载**（`/api/monitor/agent/linux-<arch>`），从磁盘目录 `QZ_PROBE_DIR` 读取
  （默认相对路径 `cmd/probe/dist`）。**二进制部署时该相对目录通常不存在，会导致探针安装报
  “下载失败: HTTP 404”**。解决：
  1. 从本项目 GitHub Release 下载 `probe-linux-amd64` / `probe-linux-arm64`；
  2. 放到一个目录（如 `/opt/qingzhou/probe/`），文件名保持不变；
  3. 在 env 里设 `QZ_PROBE_DIR=/opt/qingzhou/probe` 并重启面板。
- 告警阈值（CPU/内存/磁盘）在「系统设置 → 监控告警阈值」调整。

## 四、协议选型（抗封锁 + 速度）

| 场景 | 推荐 | 说明 |
|---|---|---|
| 主力 | **VLESS + Reality + Vision** | uTLS 指纹，无需证书，最隐蔽 |
| 弱网/晚高峰 | **Hysteria2** / **TUIC v5** | 基于 QUIC，抗丢包，跨境体验好 |
| 兼容老客户端 | VMess + ws + TLS | 走 CDN 时有用 |

每台落地同时开 1 个 Reality 入站 + 1 个 hy2 入站，用户客户端用「♻️ 自动选择」自动选最快。

## 五、运维排错

- **改完不生效**：面板每改动会重建配置；后台也有约 1 分钟的定时重建。
- **某落地下发失败**：看面板日志 `sbctl: server N apply error: ...`，多为该机 sing-box 版本
  对配置项要求不同（如 `domain_strategy` 在 1.12+ 改写）。升级/降级该机 sing-box 或调整配置。
- **统计无数据**：确认 sing-box 是**官方版（含 v2ray_api）**，且 `QZ_SINGBOX_V2RAY` 与配置里
  `experimental.v2ray_api.listen` 一致（默认 `127.0.0.1:18080`）。
- **sing-box 启动失败**：`journalctl -u sing-box -n 50`，或 `sing-box check -c /etc/sing-box/config.json`。
