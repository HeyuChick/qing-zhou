## 1. 采用的方案

轻舟面板采用**两层配置叠加**的轻量级方案，没有引入任何第三方配置库（如 viper、godotenv）：
- **进程级配置**：通过 `QZ_*` 环境变量注入，由 `internal/config` 包在启动时读取。
- **运行时/持久化配置**：通过 SQLite `settings` 表存储，由 `internal/store` 提供 `GetSetting/SetSetting` 等 API，并支持对敏感字段进行 AES-GCM 加密存储。
- **覆盖优先级**：环境变量 > 数据库设置 > 代码默认值。该规则在 `main.go` 的 `buildMailer` 与 `buildSbController` 中通过 `get(envKey, settingKey, def)` 模式统一实现。

## 2. 关键文件

| 文件 | 作用 |
|---|---|
| `internal/config/config.go` | 定义 `Config` 结构体与 `Load()`，仅加载 `QZ_LISTEN`、`QZ_DB`、`QZ_ADMIN_USER`、`QZ_ADMIN_PASS` 四个核心变量 |
| `main.go` | 唯一进程入口，组装配置、邮件、sing-box 控制器；集中实现 `env > DB > default` 的覆盖逻辑 |
| `internal/store/settings.go` | 基于内存缓存的 settings 读写 API，支持布尔/整型转换与全量导出 |
| `internal/store/crypto.go` | 敏感字段 AES-GCM 加解密，维护 `encKeys = {smtp_pass, cf_api_token}` 白名单 |
| `deploy/qingzhou.env.example` | 部署环境变量模板，列出所有 `QZ_*` 变量及注释说明 |
| `deploy/qingzhou.service` | systemd 单元，通常配合 `.env` 文件使用 |

## 3. 架构与设计约定

### 3.1 环境变量命名规范
所有进程级配置均以 `QZ_` 前缀命名，包括：
- 基础运行：`QZ_LISTEN`、`QZ_DB`、`QZ_ADMIN_USER`、`QZ_ADMIN_PASS`
- 公开地址：`QZ_PUBLIC_BASE`（覆盖设置页中的面板访问地址，设为只读）
- 探针与更新：`QZ_PROBE_DIR`、`QZ_UPDATE_REPO`、`QZ_UPDATE_GITHUB_TOKEN`
- SMTP：`QZ_SMTP_HOST/PORT/USER/PASS/FROM/FROM_NAME/SECURITY`
- sing-box：`QZ_SINGBOX_CONFIG`、`QZ_SINGBOX_V2RAY`、`QZ_SINGBOX_UNIT`、`QZ_SINGBOX_STATS_INTERVAL`
- 安全：`QZ_SECRET_KEY`（用于 at-rest 加密，推荐独立于数据库存放）

### 3.2 三层覆盖模型
`main.go` 中 `buildMailer` 与 `buildSbController` 均使用统一的 helper：
```go
get := func(envKey, settingKey, def string) string {
    if v := os.Getenv(envKey); v != "" { return v }
    if v, _ := st.GetSetting(settingKey); v != "" { return v }
    return def
}
```
即：**环境变量 > 数据库设置 > 硬编码默认值**。该模式被多处复用，是仓库内统一的配置解析约定。

### 3.3 运行时设置（settings 表）
- 通过 `store.GetSetting(key)` / `SetSetting(key, value)` 读写，首次访问时全量加载到内存 map 缓存，写操作后失效缓存。
- 提供便捷类型转换：`GetSettingBool`、`GetSettingInt64(key, def)`、`SetSettingBool`。
- `AllSettings()` 会返回全部设置（但调用方需自行过滤敏感键），测试与导出场景使用。

### 3.4 敏感信息加密存储
- 受保护字段由 `encKeys` 白名单声明：`smtp_pass`、`cf_api_token`。
- 写入时自动以 `enc:v1:` 前缀 + base64(AES-GCM) 密文存入；读取时透明解密。
- 加密密钥来源：优先 `QZ_SECRET_KEY`，回退到 JWT secret（此时日志告警提示风险）。
- 启动自检：`CountUndecryptableSecrets()` 统计无法解密的密文数量，若大于 0 则打印警告，影响 sing-box TLS inbounds 部署与 SMTP 功能。
- 新增敏感字段需在两处登记：`encKeys` 白名单 + 对应业务逻辑的 `GetSetting` 调用处。

### 3.5 初始化与种子数据
- 首次启动时通过 `st.Seed(cfg)` 创建管理员账户；若 `QZ_ADMIN_PASS` 为空则生成随机密码并记录到日志。
- JWT secret 缺失时会直接 `log.Fatalf`，保证鉴权可用。

## 4. 约定与约束

| 规则 | 依据 |
|---|---|
| 进程级配置一律使用 `QZ_*` 环境变量，禁止使用配置文件（yaml/toml/envfile） | `internal/config/config.go` 仅依赖 `os.Getenv` |
| 可编辑的业务配置存放在 SQLite `settings` 表，通过 `store` 包访问 | `internal/store/settings.go` |
| 敏感字段必须加入 `encKeys` 白名单才能享受 at-rest 加密 | `internal/store/crypto.go` 中 `encrypt()` 检查白名单 |
| 新增可覆盖的配置项应遵循 `env > DB > default` 三段式 helper 模式 | `main.go` 中 `buildMailer` / `buildSbController` 的统一实现 |
| `QZ_SECRET_KEY` 应独立于数据库保存，否则数据库泄露将同时暴露密文与密钥 | `main.go` 启动日志明确警告 |
| 修改 `QZ_SECRET_KEY` 后旧密文不可解密会导致 sing-box TLS inbounds 拒绝部署（不会降级为明文） | `main.go` 启动自检与 `crypto.go` 的 `decryptOK` 语义 |
| 面板对外地址可通过 `QZ_PUBLIC_BASE` 强制锁定，设置页对应字段变为只读 | `deploy/qingzhou.env.example` 注释说明 |

## 5. 总结

轻舟面板的配置系统非常轻量：无外部依赖、无配置文件格式，仅靠环境变量与 SQLite settings 表完成全部配置管理。其核心设计思想是**“默认值兜底 + 数据库可热改 + 环境变量强覆盖”**，并通过统一的三段式 helper 函数确保行为一致。敏感信息通过 AES-GCM 加密存储在数据库中，并以 `QZ_SECRET_KEY` 作为独立密钥源，启动时进行完整性自检，避免静默降级带来的安全风险。
